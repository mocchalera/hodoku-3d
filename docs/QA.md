# 検証記録 — HODOKU DIORAMA 2.1 / 2026-09-15

## 今回完了した検証

| 対象 | 実施結果 | レポート |
|---|---|---|
| 変更箇所の3Dブラウザ操作・描画 | 14項目 PASS | `tests/behavior/browser-report.json` |
| 2Dフォールバック・共有・保存互換性 | 20項目 PASS | `tests/3d/fallback-report.json` |
| 交通エンジン | PASS、追加60設計と全3景のクリア | `tests/engine-report.json` |
| 停止線・車体・信号・歩道の不変条件 | PASS | `tests/behavior/invariants-report.json` |

3DはChromium・ANGLE SwiftShader・Xvfbで実描画。PC 1440×1000とタッチ対応390×844で右折信号の操作を確認。追加が12pt・1手で、取り消すと返却されること、実際に矢印が点灯して主道・脇道・横断開始と競合しないこと、描画車体色が停止状態によらず固定されること、渡った人が歩道を歩き続けることを確認した。無変更の比較は改善率0。未捕捉JavaScript例外なし。

数値検証では全20流入方向について乗用車とバスの車体先端が停止線の手前に収まることを確認した。既に青で進入した車のクリア、交差点内の右折待ち、車体長を考慮した車間距離も対象。歩行者は両岸28待機位置と退出経路を全道路のアスファルト領域と比較し、待機・退出中は道路外にいること、横断の前後で座標が飛ばないことを確認した。レポート内の大量のチェック数は時間刻みごとの反復判定であり、それだけ独立したテストケースがあるという意味ではない。

全3景のクリアはエンジンとブラウザの共通ゲームUIで確認した。検証した解は順に2印・3印・2印。第2景は右折信号だけの案と高架を用いた別案でもクリアできる。全3景の最高評価は今回確認していない。設計例はエンジンレポートに含む（ネタバレ）。

フォールバックではWebGL生成を意図的に拒否して2Dに切り替えた。旧共有コード、右折信号入りの共有コード、旧保存キーからの設計復元、音・キーボード・ヘルプを確認。Storageはインメモリの同一インターフェースであり、ディスクへの実保存ではない。旧モデルの最高得点は新モデルの成績に混在させない。
