# 朝を、ほどく。3D — HODOKU DIORAMA 2.1

**手のひらの街を、三手でほどく。**

3ステージの街を本物の3Dジオラマにした交通パズルです。2.1では、停止線と車体の停止判定を統一し、右折専用信号と歩行者の横断後の動きを追加しました。回転・拡大・俯瞰・路上・車両追走で観察し、少ない介入で流れを変えるゲームです。

松本市内の公開交通量を種にした、3手・予算制約つき交通パズルです。
街を拡大するのではなく、すでにある道と時間の配り方を繕います。

## 遊ぶ

`index.html` を保存し、WebGLとJavaScriptが使えるブラウザで開いてください。ビルド、サーバー、アカウント、APIキーは不要です。絵、音、ゲーム、交通量のスナップショットを1つのHTMLに内蔵しています。外部ライブラリやフォントファイルは読み込みません。

これは配布用ファイルです。この納品物に公開サイトのURLは含まれていません。スマートフォンでURLを開くだけの配布にする場合は、この `index.html` を静的Webホスティングへ配置します。

「最初の朝へ」→交差点を選ぶ→「時を編む」「道を繕う」で変更を書き込む→「この案で、朝を流す」。すぐ結果を見たいときは「結果まで」。携帯画面には下部に「試す」ボタンがあります。

変更の取り消しと再試行は無料です。同じ設定の書き換えは手数を追加消費しません。別の設定を追加したときに1手です。予算の `pt` はゲーム用の抽象単位で、現実の工事価格ではありません。

## 立体の街を触る

| 操作 | マウス | タッチ |
|---|---|---|
| 回り込む | 地図をドラッグ | 1本指でドラッグ |
| 拡大・縮小 | ホイール、または＋／− | 2本指でピンチ、または＋／− |
| 街を横にずらす | Shift＋ドラッグ、または右ドラッグ | 2本指で移動 |
| 交差点を選ぶ | 地図の番号、または右側の01–05 | 地図の番号、または下の01–05 |
| 交差点へ寄る | 「この交差点を、近くで見る」 | 同左 |
| 全体に戻る | 「模型」または↺ | 同左 |

地図上の「模型／俯瞰／路上／追走」で視点を変えます。カメラ操作は無料です。追走は実際に流れている一台の車を追います。別の車を直接クリックして指定する機能ではありません。

**3Dの違いを見る入口：** 交差点を近くで見て、曲がり待ちと停止線の関係を観察してください。第2景では高架を購入でき、橋脚、スロープ、上を走る車、下の交差点を別々に見られます。高架だけで問題がすべて消えるわけではありません。

古いGPUやWebGLを利用できない環境では、理由を表示して2Dに切り替えます。GPU描画が途中で失われた場合はページを再読み込みしてください。保存できる環境では設計が端末内に残ります。端末の省電力や発熱などで動作が重くなる可能性があり、実機ごとの性能は未検証です。

## 三つの景

| 景 | 問い | 予算 | 目標 |
|---|---|---:|---:|
| 01 ひと針の朝 | 曲がり待ちの後ろの列を、どうほどくか | 44 pt | 総待ち時間 −18% |
| 02 青は、ひとりのものではない | 駅・学校へ向かう人に、どう時間を分けるか | 90 pt | −22% |
| 03 帰り道の余白 | 道を増やさず、信号の長さと拍で改善できるか | 28 pt | −14% |

第2景では02・04、第3景では02・03・04の右折レーンが既設です。各景は独立した問題で、前の景で選んだ工事を引き継ぐ仕組みではありません。

対策は、青の配分、青の開始時刻、全線の信号連動、右折専用信号、右折レーン、高架の6種類。高架は直進車のみ信号を回避し、下流が満杯なら高架上でも詰まります。

## 2.1で変わった動き

- 赤・黄信号では、進入前の車はバスを含め車体の先端が停止線の手前で止まります。青で進入済みの車は交差点を抜け、右折待ちは交差点内でも行います。出口側に車体が収まる空間がない場合は進入を待ちます。
- 車体色は車ごとに固定。停止時の識別にはブレーキランプと「詰まりを読む」の表示を使います。
- 歩行者は歩道で待ち、横断歩道を渡ってから反対側の歩道を歩いて立ち去ります。渡った瞬間には消えません。
- 「時を編む」→「右折専用信号をつける」で12pt・1手の追加。主道から右折需要のある02〜04で使えます。主道枠の12秒を切替4秒＋右折矢印8秒へ振り分け、対向直進と歩行者の横断開始を止めます。既に進入した車・歩行者のクリアを待つため、単なる固定時刻の灯火表示ではありません。

交通モデルを更新したため、同じ設計でも旧版と評価が変わります。共有コードと保存キーは維持していますが、旧モデルの最高得点は新版の記録へ混在させません。ブラウザが同じ保存領域を利用できる場合に旧設計を復元します。

## 勝利条件と評価

同じ20分・同じ車・同じ歩行者・同じ発車予定で、原案と変更案を比較します。

総待ち時間は人数で重み付けした **人・分**。車の速さだけでは決まりません。各景の削減目標に加え、歩行者の平均待ち時間が原案＋6秒以内、脇道利用者の平均待ちが＋15秒以内、到着車が原案から4台相当を超えて減らないことが必要です。

クリアで1印、改善率が目標＋8ポイント以上でさらに1印、使用予算60%以内でさらに1印。最大3印です。2.1では全3景のクリア解を検証済みです（検証した解の評価は順に2印・3印・2印）。全景の最高評価は今回確認していません。

地図の外で入口待ちする車、未到着の車も待ち時間に含めます。車を入れずに消して得点する仕組みにはしていません。終了時点までの評価なので、終了後の残留交通の解消時間を予測するものではありません。

音は初期OFF。右上からONにすると、車が街を抜ける動きに合わせて小さな音が鳴ります。成績と案はブラウザのStorageが利用できる場合のみ端末内に保存し、使えない場合もゲームは動きます。

結果画面の「この案を共有する」で設計コードを渡せます。受け取った人は「データと制作」→「共有された案を読み込む」から再現できます。公開ホスト上では設計を含むハッシュURLも作れます。

キー操作：1–5で交差点、Spaceで停止／再生、Bで原案比較、Zで最後の変更を戻す。Oで模型、Tで俯瞰、Cで路上、Fで選択交差点へ寄る。入力欄・ボタンにフォーカスがある間は標準のキーボード操作を優先します。

## ソース構成と改修

```text
index.html                 そのまま配布する完成ゲーム
src/index.template.html    HTML構造
src/style.css              紙・文字・余白・レスポンシブUI
src/data.js                出典付き観測値
src/engine.js              DOMから独立した交通モデル
src/renderer3d.js          ネイティブWebGL、立体メッシュ、影、視点、タッチ
src/renderer2d.js          WebGL非対応時の2Dフォールバック
src/style3d.css            ジオラマ版のUI・レスポンシブ調整
src/app.js                 操作・評価画面・音・共有・保存
build.py                   単一HTMLを再生成
serve.py                   任意のローカルHTTPプレビュー
preview.png                実際の3Dブラウザ画面
data/                      観測値／ゲームパラメータのJSON
docs/                      設計意図・モデル・検証記録
tests/                     エンジン／ブラウザテストと結果
```

```sh
python3 build.py
node tests/engine.test.cjs
python3 serve.py
```

`serve.py` は端末自身だけに公開するローカルサーバーです。インターネット公開ではありません。

ブラウザの自動テストはPythonのPlaywrightとChromiumが必要です。

```sh
python3 -m pip install playwright
python3 -m playwright install chromium
node tests/behavior/invariants.cjs
xvfb-run -a python3 tests/behavior/browser.py
xvfb-run -a python3 tests/3d/fallback.py
```

既存のChrome/Chromiumを指定する場合は `CHROMIUM_PATH` 環境変数を使えます。テストは独立した一時プロファイルで動きます。Linuxのヘッドレス環境ではXvfbが必要になることがあります。GUI環境では `xvfb-run -a` を省略できます。

## 検証状況

今回の実施結果は `docs/QA.md` を参照してください。変更箇所を中心にChromiumの実際のWebGL描画で14項目、2Dフォールバック・互換性で20項目を確認しました。右折信号の追加・取り消し・点灯、固定車体色、歩道を立ち去る歩行者、390px幅の操作を含みます。旧版の3D回帰テスト一式は今回は完走していません。

交通エンジンは全ステップの車・歩行者数の保存、同一需要、車体を考慮した車間距離、信号の排他、決定性、60通りの追加設計、全3景のクリアを再検証しました。追加の幾何テストでは全20流入方向の乗用車・バスの先端が停止線を越えないこと、歩行者の待機・退出経路が全道路の外側であることを確認しました。観測データ、既存の予算・目標は変更していませんが、停止・右折・歩行者のモデルは変更しています。

**未検証：実機iPhone/iPad・Safari、端末GPUでの実フレームレート、ディスク上のStorageへの実保存、file://・公開サーバー経由の実遷移。** 制作環境ではURLへのナビゲーションが制限されるため、テストは完成HTMLをPlaywrightの `set_content` で直接読み込んでいます。公開URLへの配置は行っていません。

詳細な3D実装と制限は `docs/3D_ARCHITECTURE.md` に記載しています。

## 拡張するときに残すべきもの

地図や現実の観測点を増やす前に、1つの小さな変更が流れを変える手応えを維持すること。ゲーム結果を現実の工事効果だと表現しないこと。予算・手数・他者への影響を同時に見ること。

実地の再現を目指す段階では、道路形状だけでなく右左折交通量、信号現示、OD、飽和交通流率、観測渋滞長などで別途校正・検証が必要です。本版は交通設計業務や防災判断に使うものではありません。
